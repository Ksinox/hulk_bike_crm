# Картинки деталей для прайса запчастей — задание для Codex

CRM «Халк Байк», выпуск 2.0.2. В прайсе запчастей 766 позиций: скутер разобран
по зонам (кузов, управление, двигатель…) и узлам. Одна деталь на разных моделях —
это несколько строк прайса, но **картинка у детали одна**. Всего деталей — **358**.

Задача: нарисовать каждую деталь в одном стиле, чтобы в CRM её было видно
в карточке «как в интернет-магазине», и сразу понятно, где она стоит на скутере.

## Что сделать

На каждую деталь — две картинки:

| Файл | Что на картинке | Сколько |
|---|---|---|
| `{image_key}.webp` | крупный план детали на белом фоне | 358 |
| `{image_key}-where.webp` | «рентген» скутера, деталь подсвечена зелёным на своём месте | 344 |

Расходники (зона «Расходники»: масла, жидкости, химия — 14 шт.) на скутере не
покажешь, у них только крупный план: в данных `scene = none`, `file_location` пустой.

**Всего 702 картинки.**

## Данные

Всё лежит в этой папке. Файлы собирает `scripts/seed/repair-price-catalog.py` —
руками их не правим, правим скрипт и перезапускаем.

| Файл | Зачем |
|---|---|
| `images.jsonl` | **основной вход**: одна строка на деталь, готовые промпты и имена файлов |
| `images.csv` | то же самое для Excel (разделитель `;`) |
| `PARTS.md` | список деталей по зонам и узлам — посмотреть глазами |
| `catalog.csv` | все 766 строк прайса: код, модель, закуп, цена; с картинкой связаны через `image_key` |
| `works.csv` | прайс работ (107 работ) — картинки не нужны |

Поля строки `images.jsonl`:

| Поле | Пример |
|---|---|
| `image_key` | `drive-belt` — имя файла, латиница и дефисы |
| `zone`, `group` | `Трансмиссия`, `Вариатор` |
| `part_ru`, `part_en` | `Ремень вариатора`, `CVT drive belt` |
| `location_en` | где стоит на скутере: `CVT variator on the left side of the engine` |
| `scene` | `petrol` — бензиновый скутер, `electric` — электро, `none` — без рентгена |
| `applies_to` | модели и размеры: `810×17,5 — Yamaha Gear 4T; 660×16,5 — Yamaha Jog 4T, Vino 4T; …` |
| `price_from_rub`, `price_to_rub` | разброс цены по моделям — только для справки |
| `file_product`, `file_location` | `drive-belt.webp`, `drive-belt-where.webp` |
| `prompt_product`, `prompt_location` | готовые промпты (английский) |

## Стиль — одинаковый для всех 702 картинок

### Рентген — `{key}-where.webp`

- фон сплошной тёмно-синий `#0E1726`;
- скутер **строго сбоку, нос вправо** (так смотрит вся техника в CRM), целиком,
  по центру, около 80 % ширины кадра;
- корпус полупрозрачный, как на рентгене: тонкие стально-голубые линии `#9FB4C8`
  примерно 40 % непрозрачности, внутренние узлы едва видны сквозь пластик;
- деталь — сплошная, **фирменный зелёный `#6CAD2F`**, мягкое свечение, тонкий
  белый край, на своём настоящем месте и в своём масштабе;
- мелкая деталь (лампа, сальник, болт, датчик) — на своём месте плюс мягкое
  зелёное светящееся кольцо вокруг, чтобы её было видно;
- глушитель и всё, что стоит справа, видно сквозь корпус (мы смотрим на левый бок);
- **никакого текста**: ни подписей, ни стрелок, ни цифр, ни логотипов, ни водяных знаков;
- два базовых скутера: бензиновый городской 50–150 см³ (`scene = petrol`) и
  электро с мотор-колесом и батареей под сиденьем (`scene = electric`).

### Крупный план — `{key}.webp`

- белый бесшовный фон `#FFFFFF`;
- одна деталь по центру, занимает около 70 % кадра;
- ракурс у всех одинаковый: три четверти спереди-слева, чуть сверху;
- мягкий студийный свет, лёгкая тень под деталью;
- деталь новая и чистая, настоящие материалы (чёрный ABS, крашеный пластик,
  алюминий, сталь, резина);
- без марок и логотипов (эмблема — условный значок без надписи), без упаковки,
  без рук, без текста;
- расходники — в простой таре без марки, этикетка пустая.

### Формат

- **квадрат 1:1**. Исходник генерировать 1024 × 1024 PNG.
- В CRM класть **WebP 640 × 640, качество 82** (≈ 30–50 КБ на картинку,
  все 702 — около 25 МБ).
- Почему квадрат, а не 4:3: одна и та же сетка карточек на телефоне, планшете
  и компьютере, в узкой колонке 4:3 режется.

### Почему на картинке нет названия и цены

- цены меняются — директор правит прайс в CRM, зашитая в картинку цена устареет;
- генераторы картинок портят русский текст;
- карточку «картинка + название + цена» CRM соберёт сама из прайса
  (см. «Как это встанет в CRM»).

## Как добиться одинакового стиля

1. **Два базовых рентгена без подсветки** — `_base-petrol.png` и
   `_base-electric.png`. Промпт — `prompt_location` любой детали нужной сцены,
   но вместо фразы «Only one part is solid and highlighted…» написать
   «No part is highlighted». Показать заказчику и утвердить.
2. **Каждую `-where` картинку делать правкой базы** (image edit, база на входе):
   «Keep this image exactly the same: same scooter, same outlines, same background.
   Only highlight {part_en} ({location_en}) …» — дальше текст из `prompt_location`.
   Тогда скутер одинаковый на всех 344 картинках, меняется только подсветка.
3. **Крупные планы**: первые три утверждённые картинки передавать как образец
   стиля к остальным.
4. **Пилот — 13 деталей**: по одной на зону, одна мелкая и одна электро. Показать заказчику,
   поправить промпты, потом вся партия:

   `front-cover`, `grips`, `headlight`, `bulb-position`, `battery`, `piston-kit`,
   `drive-belt`, `muffler`, `radiator`, `drum-shoes`, `front-fork`,
   `engine-oil-1l`, `ev-battery`.

Если генерировать через API — например, OpenAI Images (`gpt-image-1`,
`size=1024x1024`, `quality=high`, непрозрачный фон; для `-where` — метод правки
с базой на входе). Скрипт должен:

- пропускать уже готовые файлы, чтобы его можно было перезапускать;
- ограничивать число параллельных запросов и повторять при ошибке;
- вести журнал `docs/parts-catalog/images-status.csv`:
  `image_key;product;location;note` (`ok` / `fail` / `redo`).

## Куда класть

- исходники PNG — `parts-images/masters/` в корне репозитория. Папка уже
  в `.gitignore`, в git не попадёт (это около 1 ГБ);
- готовые WebP — `apps/web/public/parts/{image_key}.webp` и
  `apps/web/public/parts/{image_key}-where.webp`;
- имя файла — ровно `image_key` из списка.

## Проверка каждой картинки

- **деталь та самая.** Ролики вариатора — это грузики-цилиндры, а не подшипники;
  сальник — резиновое кольцо; ЦПГ — цилиндр с поршнем. Если сомнение — искать
  фото детали по `part_en` и названию модели из `applies_to`;
- **подсветка на месте**: вариатор — слева, между сиденьем и задним колесом;
  глушитель — справа внизу у заднего колеса; бак — под сиденьем или под полом;
  аккумулятор — под сиденьем или в полу; см. `location_en`;
- нет текста, логотипов, водяных знаков;
- фон, ракурс и масштаб как у остальных;
- в конце собрать контрольный лист — сетку превью по зонам — и пройтись глазами.

## Как это встанет в CRM (сделаем, когда будут картинки)

- у каждой из 766 позиций прайса уже записан ключ картинки
  (`price_items.image_key`);
- CRM будет брать `/parts/{image_key}.webp`:
  - миниатюра в окне «Из прайса» и в подсказках при вводе названия;
  - по нажатию — карточка детали: крупный план ⇄ «где стоит», название,
    модели, цена; закуп — только тем, у кого есть право видеть прибыль ремонтов;
- нет файла — строка остаётся как сейчас, без миниатюры, ничего не ломается;
- позиции, которые сотрудники добавили сами из ремонта, картинки не имеют —
  к ним можно будет прикрепить своё фото.

Карточка детали:

```
┌──────────────────────────────┐
│                              │
│      [ крупный план ]        │  ← нажатие: «где стоит»
│                              │
├──────────────────────────────┤
│ Ремень вариатора — 810×17,5  │
│ Yamaha Gear 4T               │
│ 1 250 ₽          закуп 890 ₽ │
│                  [ Добавить ]│
└──────────────────────────────┘
```
